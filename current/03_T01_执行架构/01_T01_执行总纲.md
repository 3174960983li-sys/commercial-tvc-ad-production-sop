# T01｜AI商业广告全流程执行架构与任务调度总纲 V1.0

> 项目：《AI商业广告全流程制作 SOP V1.0》  
> 层级：第三阶段 T01（操作架构），不修改第二阶段定稿标准  
> 依赖基线：《01_架构基线_V1.0.md》《08_S07跨阶段统一规则_V1.0.md》及P0–P11定稿规范  
> 状态：T01设计完成；尚未进行真实商业项目端到端运行验证  
> 日期：2026-11-02

## 1｜T01的职责范围和排除项

**目标：**将已批准的12阶段、99项步骤、10主Gate及10个横向管理系统组织为可运行的项目工作流。回答“何时启动、由谁执行、等待什么、何时审核、何时并行、何时回退、何时结束”。

**纳入：**任务依赖与就绪判定、任务并行、按镜头及交付变体拆分、Gate调度、角色职责、输入输出交接、异常分流、可选阶段、多版本和项目关闭条件。  
**不纳入：**99步的详细操作教程（T02）、完整的填写模板（T03）、生产级Agent/Skill实现（T04）、自动化程序和工具配置（T05）、真实广告生产试跑（T06）。

保留第二阶段S07的规则优先级：法律及平台强制要求 > 获授权且合法的客户约束 > 已冻结架构 > S07统一规则 > 阶段标准 > 第三阶段方法与Skill默认值。T01是执行解释层，**不能改变已经锁定的标准、镜头意图或审核权限**。

## 2｜三层调度：项目 / 任务 / 生产对象

| 层级 | 主要责任 | 执行单位 | 调度目标 |
|---|---|---|---|
| L1 项目总控 | 项目立项、阶段基线、预算风险、客户决策、Gate | project_id及阶段 | 受控推进，不越权放行 |
| L2 步骤调度 | 输入验真、依赖、工作分配、完成物、异常与适用性 | step_instance_id | 使99项步骤能够追踪到责任人及批准结果 |
| L3 生产对象调度 | 单镜、单资产、单Take、单派生版、素材QA和细粒度返工 | shot_id / asset_id / attempt_id / variant_segment_id | 允许镜头级并行但不丢失整片级一致性 |

`step_id`是规范定义，不是一次执行；一个项目可对`P8-04`创建多个不同`shot_id`的`step_instance_id`，但不因此增加第100个规范步骤。重复执行要保留attempt与版本。

## 3｜执行启动和预配置

### 3.1 项目入口最小信息

创建项目时记录：`project_id, project_type_axis, source_mode, target_market, platform_candidates, project_mode(REAL_CLIENT/INTERNAL_BRAND/PORTFOLIO), project_owner, approval_matrix, initial_budget, initial_schedule, P11_scope, data_access_scope`。未确认的输入可标`TO_VERIFY`，不得伪造已批准事实。

### 3.2 路线选择：采用多轴叠加而非单标签

- 传播目标：品牌认知 / 产品教育 / 销售转化 / 活动发布；确定主目标和辅助目标。
- 创意：概念隐喻 / 叙事 / 产品演示 / 人物见证 / 视觉动态，可混合。
- 渠道：电视/CTV/OTT / 在线视频 / 社交平台 / 电商 / 线下屏，按交付版本分别记录。
- 生产：`AI / LIVE / CG / HYBRID`，由镜头级真实来源决定，项目级只标主方案。

所有阶段仍保留；条件性步骤按**项目和对象范围**记录`REQUIRED / CONDITIONAL / NOT_APPLICABLE`及判定理由。`NOT_APPLICABLE`不是Gate PASS、不是缺少数据的快捷替代状态。镜头无旁白时可以将独立配音动作标N/A，但P9-07仍应确认“无配音需求”，不无证据删除步骤。

### 3.3 两次计划冻结

- G0后：冻结商业范围初版（目标、交付渠道、责任人、预算上限、需核实事项）。
- G6后：冻结可执行生产计划（经G5批准的镜头、已批准资产、生产路线、镜头成本预算和验收目标）。

若中途出现变更，提交M02变更单，仅重新打开受影响的对象和Gate，不自动把所有项目工作倒回P0。

## 4｜12阶段主路径与阶段Gate

```text
P0 立项 --G0--> P1 调研 --G1--> P2 策略 --G2--> P3 创意 --G3-->
P4 脚本 + P5 导演（允许受控并行） --G4联合审批-->
P6 分镜/Animatic --G5--> P7 正式资产/生产计划 --G6-->
P8 草稿/等效动态验证 --G7a--> 正式镜头生产 --G7b-->
P9 后期成片候选 --> P10 逐交付版本审查 --G8-->
真实交付及验收记录 --> P11 投放/制作复盘(若启用) --G9-->
项目归档
```

- `G0–G9`为10个**主**Gate；`G7a/G7b`为G7内部的两个子Gate。
- P4和P5不是“P4必须全部完成后才能启动P5”：可在G3后并行推进导演概念及脚本；但G4只在Script Master与Director Bible联合完成并批准后放行。
- P6可以用合规的概念参考和代理图进行预演，不要求等P7正式资产；G5后制作正式资产。如资产发现镜头可行性问题，走M02局部变更。
- P9可以在G5后做非锁定代理粗剪，不得把代理粗剪视作正式G7b素材或G8批准。
- P10的技术/版权预查可在前期并行进行，只有最终**具体交付文件**生成后才能做G8的最终hash核验。
- P11是交付后的独立可选分支，不启用时记录`P11_NOT_ACTIVATED`和`G9_NOT_APPLICABLE`，不可假装G9 PASS。

## 5｜步骤调度基础语义

每个`step_instance`必须至少具有：`step_instance_id,project_id,step_id,scope_type,scope_ids,applicability,task_status,owner,reviewer,hard_dependencies,soft_dependencies,required_gate_evidence,inputs,outputs,findings,blocking_reasons,created_at,updated_at`。

### 5.1 任务状态（新增在执行层，不能混成S07原有的`artifact_status`）

| task_status | 含义 | 可执行动作 |
|---|---|---|
| WAITING_FOR_INPUT | 缺少必要输入/证据 | 补齐已知材料，不启动正式工作 |
| READY | 强依赖及当前Gate满足 | 领取任务或自动派发 |
| IN_PROGRESS | 负责人正在执行 | 生成新的候选交付物及日志 |
| IN_REVIEW | 完成物提交步骤审查 | 审核，不可当作Gate PASS |
| REWORK_REQUIRED | 当前成果被退回 | 按变更记录返工并重新审查 |
| BLOCKED | 法规、客户、风险或关键依赖阻断 | 原因未解除不得继续 |
| DONE | 步骤完成且所需内部审查成立 | 其合格输出可解锁下游，**不代表阶段Gate PASS** |
| NOT_APPLICABLE | 经过授权判定不适用 | 留依据，不视作完成了对应生产 |

任务状态与S07的`artifact_status`、`gate_decision`、`media_qa_status`、`delivery_status`各自独立；不能以任务DONE推断视频可商用或客户已批准。

### 5.2 就绪判断

一个任务可标READY，当且仅当：①本任务适用；②必要上游输入确有可追踪版本；③所有hard dependency满足（当前对象范围）；④上游必要Gate有效且其版本未失效；⑤责任人可执行，必要的授权及资料安全条件满足；⑥预算/时间资源风险在批准范围。soft dependency可以先行但需要标明假设及受控风险，正式锁定前补齐。

条件Gate只能授权**明确命名、不依赖未结条件**的动作，绝不能跨越事实、权利、法律或核心传播风险。

### 5.3 冲突与抢占

当多个任务竞争资源，默认优先顺序：硬性合规与安全阻断处置 > 关键路径上的已到期审批与缺失依赖 > 可解锁大量下游任务的核心资产/镜头 > 即将超支的成本风险 > 其他并行任务。该优先级是默认调度建议，项目制片可在不违反强制约束时调整。

## 6｜阶段并行与锁定策略（阶段级）

| 阶段区间 | 允许并行 | 必须串行/统一放行 | 不允许的捷径 |
|---|---|---|---|
| P0 | 需求整理、初步预算/渠道风险确认在信息充分后交错 | G0必须确认项目范围和批准权限 | 未证实Brief当已批准 |
| P1 | 品牌、产品、竞品、受众多线研究 | P1-07汇总后G1 | 未证实产品效果直接进入宣称 |
| P2 | 商业目标/受众研究与价值主张准备可迭代 | 主传播信息批准后G2 | 没有统一策略就承诺创意 |
| P3 | 多创意方向可平行探索 | P3-07选择及G3 | 未经客户授权改变目标 |
| P4–P5 | 脚本和导演视觉概念并行，使用受控草稿接口 | G4联合锁定Script Master、Director Bible | 用导演直觉替代商业事实 |
| P6 | 镜头功能/构图/运动可协同开发，代理图制作 | Animatic整体检查后G5 | 把代理图作为正式商业资产 |
| P7 | 产品、角色、场景、道具可分线生产；工具链评估并行 | 主版本一致性及镜头映射完成后G6 | 使用未授权/不准确资产进正式生产 |
| P8 | **按镜头/任务并行**，已过G7a镜头可先生成正式素材 | 单镜经G7b可交后期；整片应有完整已验收素材集合 | 失败草稿硬拉高清或以单镜PASS代替全片PASS |
| P9 | 代理粗剪、字幕准备、音乐方案、声音准备可以并行 | 正式母版及其音画、权利完成后交P10 | 非锁定代理直接当正式母版 |
| P10 | 多交付版技术检查可并行，客户审片与修改循环 | **每个实际输出文件**通过G8后才能正式交付 | 以母版G8替代多语言、多画幅的G8 |
| P11 | 数据分析、成本和问题复盘可独立展开 | 结论归档并经G9关闭（启用时） | 无数据硬给出因果增量结论 |

## 7｜镜头级生产调度规则

### 7.1 镜头队列

`SHOT_PENDING → SHOT_INPUT_READY → DRAFT_TESTING/VALIDATING_EQUIVALENT → G7A_RELEASED → FINAL_PRODUCTION → G7B_RELEASED → POST_READY`仅表示镜头队列视图，不替代task/media/Gate的标准状态记录。

每个shot可以拥有多个`production_task_id`、多个`attempt_id`、多个候选`take_id`；正式使用哪一条take由明确的选择和媒体QA结果决定。生成失败的attempt可以没有有效媒体或take。

### 7.2 AI草稿与非AI等效验证

- AI：草稿必须检验镜头的主体行动、产品一致性、机位和空间、动作完成、入出点及生成成本；通过G7a后才批准该镜头的高清任务。
- LIVE/CG：可用测试摄影、阻挡预演、预可视化、技术验证等**有记录的等效证据**通过G7a；不伪造AI草稿。
- HYBRID：每个相关来源都需记录合成条件，例如关键帧、视线、绿幕、产品插入和轨迹匹配；不能仅按其中一个来源通过就视为最终合成素材可用。

### 7.3 镜头和整片进度不混淆

- 单镜G7a通过允许该镜头正式生产；G7b通过允许该镜头进入**锁定后期素材池**。
- 若镜头A通过、B仍失败，后期可以使用A开始受控精剪，但整条母版仍无法宣布镜头集合完整。
- 共享资产更新可能使多个镜头G7a/G7b失效；需按影响映射批量标记复审，而不是全部或毫无理由地保留旧审批。

## 8｜交付变体调度规则

1. 先在P0建立意向交付清单；P4–P6决定不同版本需保留的内容、时长与构图约束；P9–P10生成实际交付变体。
2. 每个`delivery_variant_id@version`绑定独立`variant_timeline_id`、市场、语言、渠道、尺寸/帧率、字幕/CTA、rights_scope和实际输出hash。
3. `shot_id`可被多个变体复用，但不同入出点或画幅位置需要独立`variant_segment_id`；如导演意图不同，则创建新shot_id并留映射。
4. 在P10-09导出后的**最终文件**上进行G8审核，检查文件内容、产品事实、商标、安全区、字幕、技术、授权和客户批准；再次重新编码生成了新hash时，需确认内容/技术是否变化并记录新的审批范围，不隐含承袭旧hash批准。
5. `G8 PASS`只等于授权交付；`DELIVERED`、`RECEIPT_CONFIRMED`、`CLIENT_ACCEPTED`按证据推进，模拟作品集不得写成真实客户批准。

## 9｜角色、审批与可兼职边界

| RACI责任面 | 单人制作 | 小型团队 | 不能自动替代的权威来源 |
|---|---|---|---|
| 项目制片/协调 | 创作者兼制片 | 项目制片 | 客户的商业决策、合同范围 |
| 品牌/策略 | 创作者兼策划 | 策略负责人 | 产品真值、营销宣称证据 |
| 创意与脚本 | 创作者兼文案 | 创意/文案负责人 | 获权客户的创意/品牌确认 |
| 导演与资产 | 创作者兼导演和美术 | 导演、美术与资产设计 | 资产真实权利、品牌规范 |
| AI及混合生产 | 创作者兼技术制作 | AI/实拍/CG执行负责人 | 平台政策、第三方素材许可 |
| 后期与输出 | 创作者兼剪辑和音频 | 后期负责人 | 客户验收和发布放行 |
| 合规与审片 | 创作者负责内部检查并记录限制 | 指定合规审核者及客户审批者 | 法律意见、必要第三方及客户授权 |

一个自然人可以拥有多个`responsible_role`，但**AI不能代替真实广告主签署品牌事实与投放批准**；个人作品集采用`SIMULATED_APPROVAL`，不能写`CLIENT_ACCEPTED`。

## 10｜阶段完成条件与项目结束

- `phase_completed`须所有必需步骤在相应对象范围DONE或经批准N/A、必要交付物齐全、阶段Gate有有效审核证据；已经被上游变更失效的Gate不得使用。
- `project_production_complete`：经批准的最终各版本达到G8、交付证据记录完整；合同要求验收的项目还需要客户验收事实与相关未闭问题处理。若未达到合同验收不能宣称“客户验收完成”。
- `project_review_closed`：P11启用且G9通过；未启用则保留`P11_NOT_ACTIVATED/G9_NOT_APPLICABLE`。
- `portfolio_only_complete`：仅用于模拟广告，无客户批准或实际投放背书。数据、权利不因此免除。

## 11｜T01交付与T02接口

T01交付：①本执行总纲；②99步骤任务依赖/并行路由矩阵；③Gate与异常处理决策树；④设计阶段静态验收案例。T02应以各步骤的依赖及批准版本为输入，为每步补“实际操作方法、工具选择、操作次序、异常处置样例、可验收产物”；不修改其ID和跨阶段管理权限。

**T01验收性质：**规范级逻辑一致性与文本/数据结构核验，不宣称已经创建可执行软件、模型平台连接器或实际客户广告。
