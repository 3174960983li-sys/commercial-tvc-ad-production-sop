# T01｜Gate决策、异常与回退调度规则 V1.0

> 适用：从接单至交付的真实与模拟广告项目。任务就绪、Gate审核、素材QA、法律证据状态互不替代。对应S07 R01–R12。

## 1｜强制门禁检查序列

针对任意正式生产或交付动作，按照以下顺序审核：

1. `scope`：核对当前是项目/阶段/shot/take/variant中哪个对象，确认被审批对象的确切ID和版本。
2. `applicability`：确认必做、条件执行或有根据的N/A。
3. `dependencies`：所有强依赖的产物确实存在并具备合格版本；若失败，任务`WAITING_FOR_INPUT`。
4. `gate`：所依赖的Gate是否对**当前版本、当前对象、当前动作**有效；失效或缺席时`BLOCKED`/`HOLD`。
5. `evidence/rights`：检查宣称、肖像、商标、音乐、字体、素材及渠道权利；未知不自动通过。
6. `budget/resource`：确认授权范围、风险阈值、预算和时间约束。
7. `execute`：满足条件后才令任务`READY`/`IN_PROGRESS`；完成后生成带版号的产物并申请相应审核。

## 2｜审核结果路由

| Gate决定 | 合法动作 | 禁止动作 | 后续要求 |
|---|---|---|---|
| PASS | 按批准版本和scope推进 | 将单镜批准延伸为全片批准 | 保留批准人、hash、时间及适用条件 |
| CONDITIONAL | 仅允许明确许可且不依赖未结项的部分动作 | 越过事实、法律、权利、产品或重大缺陷 | 为每条条件创建condition_id及责任人 |
| REWORK | 将影响对象转入返工任务 | 再使用已被退回产物作为正式输入 | 根因→最早错误阶段→局部修复→复审 |
| HOLD | 暂停受影响正式任务，继续无关部分 | 把未知标N/A或PASS | 明确缺少的资料、批准人、证据及解锁事件 |

## 3｜异常类型与最小回退原则

| 根因类别 | 优先排查 | 默认回退层 | 最小影响范围示例 |
|---|---|---|---|
| BRIEF_CHANGE | 客户需求、交付范围 | P0 / G0 | 增加新市场版本，评估全链影响 |
| FACT_OR_CLAIM | 产品SKU、功效、数据、表达暗示 | P1 / G1，必要时P2/P4 | 删除错误卖点并重审相关镜头/字幕 |
| STRATEGY_CHANGE | 人群、主传播信息、CTA | P2 / G2 | 受影响beat及其镜头/变体 |
| CREATIVE_MISFIT | 创意和品牌定位不一致 | P3 / G3 | 受影响段落与镜头，不默认全片 |
| SCRIPT_ERROR | 文案、叙事节拍、旁白 | P4 / G4 | 关联beat、shot、VO及字幕 |
| DIRECTION_ERROR | 摄影原则、人物表演、视觉规范 | P5 / G4 | 受影响镜头及视觉资产 |
| STORYBOARD_ERROR | 轴线、起落幅、动作时长 | P6 / G5 | 受影响shot及Animatic时轴 |
| ASSET_ERROR | 包装、角色、场景空间母版 | P7 / G6 | 引用同资产版号的所有镜头 |
| EXECUTION_ERROR | 模型运动、物理错误、生成异常 | P8 / G7a或G7b | 单一attempt/take优先 |
| POST_ERROR | 调色、音效、字幕或合成 | P9 / P10关联验收 | 对应variant_segment与交付版 |
| RIGHTS_RISK | 许可到期、地域或用途限制 | 最早使用该内容的阶段 | 涉及该媒体/音乐/Logo的全部交付版 |
| PLATFORM_CHANGE | 渠道规格或政策更新 | P0目标版本 + P9/P10复核 | 受影响平台变体；必要时回P6构图 |
| BUDGET_RISK | 生成/实拍/后期超支 | M06 + 所属步骤 | 暂停超额部分，不可私自简化已批准镜头 |

变更单必含`change_request_id,source_artifact@version,change_reason,changed_fields,affected_ids,affected_variant_ids,proposed_cost_delta,decision_owner,approval_evidence,recheck_gates`；已冻结产物不能原地覆盖。

## 4｜三类典型异常决策

### A. 已批准AI镜头的产品包装变形

- 若仅是某次生成随机形变，保留原`shot_id/asset_id`，新建`attempt_id`重试，失败者保留成本记录。
- 若产品母版就错误，修订P7资产，列出**所有引用这一资产状态**的shot；重审G6、对应G7a/G7b、P9以及受影响G8。
- 若产品事实或宣称失实，追溯到P1/P2/P4，不能只用后期遮挡绕过事实审核。

### B. 16:9成片合格，但需要新增9:16信息流广告

- 首先核对Brief是否含9:16；新增范围则须M02审批成本/交付。
- 重新建立`delivery_variant_id`及`variant_timeline_id`；不必为每个同一导演镜头重复创建`shot_id`，但要按实际使用建立`variant_segment_id`。
- 评估安全区、主体位置、Logo和字幕、内容节奏及权利；裁切不成立时回P6镜头构图或P8重新生成。
- 每一个最终导出文件必须独立获G8 PASS，不沿用横屏文件hash批准。

### C. 客户只要求修改一句旁白

- 核对变更是否改变事实性宣称、受众或核心传播信息；若仅为合法措辞修饰，通常P4文本版本→P9重新录制/混音→P10重新审查关联成片。
- 如果出现未经证明的产品功效，需回P1/P2获取证据并评估脚本和镜头是否需要重做。
- 变更后重新输出的文件hash变化，不得直接沿用旧G8批准。

## 5｜人工权限与项目模拟边界

- AI/Agent可草拟需求、标识缺口、建议Gate结论、发起变更请求和执行已获权限的生产任务；不能伪装广告主、法务、平台或客户完成真实外部批准。
- 单人作品集使用`project_mode=PORTFOLIO`，以`SIMULATED_APPROVAL`、`PORTFOLIO_CLOSE`标识模拟生产；**不得**把演练结果表述为真实商业投放或客户验收。
- 需要实拍、第三方音乐、品牌资产上传或商标使用时，必须具备相应实际使用授权；合同、行业通行做法、模型服务条款互不自动代替。

## 6｜本工作包的动态执行规则（不是第二阶段修改）

- 阶段级串行仅表示正式放行顺序；一个阶段内部可以并行、返工；下一阶段可做受控探索，但不能假装Gate获批。
- 当复杂度较低的广告不涉及人物/对白/实拍时，步骤可以经审查记录NOT_APPLICABLE；不能删除步骤ID、抹去质量门槛或假定产品授权已无需求。
- G9在P11启用后才需要关闭，真实投放数据不可用时只做有证据的生产复盘。
- 若多版本共同依赖某个共享资产，变更该资产会重算这些变体的依赖和受影响Gate，不必无理由否定无关资产。
