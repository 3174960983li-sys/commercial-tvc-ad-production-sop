# T01｜99项工作步骤任务依赖与路由矩阵 V1.0

> 该矩阵是**第三阶段执行编排建议**，不改变第二阶段步骤规范的责任与适用条件。`*`=满足项目适用性时才需完成；`[条件]`=按真实审查结果分支；同一阶段步骤可迭代，而非所有行一律线性顺序。特殊前置条件与M02变更由总纲和异常路由规则共同解释。

## 使用方式

1. 读取对应阶段S00–S06步骤规范，再读取本矩阵的路由依赖；两者冲突时遵守S07优先级。
2. 默认每条步骤继承所在阶段入口Gate，表格中列出的具体先决依赖进一步限定其执行时机；允许**提前做非锁定探索或代理工作**，不意味着取得正式Gate授权。
3. 只在具备来源证据时标记依赖完成；不能因为人员在同一会议中口头讨论，就把上游文档状态直接升级为LOCKED。
4. P8步骤实例按`shot_id`/生产任务创建、P10步骤实例按交付变体创建；P11按项目与数据源创建实例。一个规范步骤可以有多个执行实例。
5. 表中依赖是最低执行编排基线，不替代项目级适用性和变更影响评估。

## 边界提醒与版本约束

- 所有阶段内部的验收规则仍以S07定稿的步骤卡为准；本矩阵中“可并行”仅表示**可在依赖就绪时并行**。
- 当步骤属于权利、宣称或品牌事实核验时，`*`不得用于绕开法律、合同或渠道硬要求。
- P8-06和P10-08为返工/修改分支，正常顺利时可无触发；他们不是所有镜头都必须失败一次的固定流程。
- P9-04修复合成只在有此需求时强制执行；“无此需求”也应有审查依据。
- 任务级有向无环图（DAG）只描述**已批准版本上的正向依赖**。返工循环通过M02 `change_request_id`新版本开启，不能直接在原DAG添加回边形成无限循环。
