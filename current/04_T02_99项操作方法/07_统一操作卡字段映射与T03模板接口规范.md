# T02-07｜统一操作卡字段映射与T03模板接口规范

## 1. 目的

99项操作方法已覆盖工作目标、输入、责任、操作、判断、输出、验收和回退，但不同批次的字段标签存在同义写法。T03不重写方法内容，而是把它们映射到统一的可填写模板与机器可读结构。

## 2. 统一字段模型

| 规范字段 | 统一键 | 现有文档常见别名 | T03要求 |
|---|---|---|---|
| 步骤身份 | `step_id/name/stage_id` | P0-01、工作步骤编号 | 必填、引用99项冻结清单 |
| 工作目标 | `objective` | 工作目标、目标、执行目标 | 必填 |
| 适用条件 | `applicability` | 适用范围、适用性、N/A条件 | 必填，支持强制/条件强制/可选 |
| 启动条件 | `entry_conditions` | 启动与输入、启动条件、启动路由、准入 | 必填 |
| 输入材料 | `inputs` | 前置输入、输入资料及其来源 | 每项记录来源、版本、权限 |
| 执行角色 | `owner_role` | 负责人、执行岗位、执行与复核、执行责任 | 必填；个人模式可由一人兼任多角色 |
| 协作角色 | `collaborators` | 参与/协作/会签角色 | 按步骤需要配置 |
| 执行动作 | `actions` | 实际执行、详细操作步骤、可直接执行的操作顺序 | 必填，动作可检查 |
| 关键判断 | `decision_points` | 关键判断、关键判断与禁止事项 | 必填 |
| 输出成果 | `outputs` | 最小输出字段、最小交付字段、本步产出、规范要求的输出与数据 | 必填，含artifact与字段定义 |
| 验收标准 | `acceptance_criteria` | 完成检查、完成判定、自检与正式验收 | 必填，区分步骤完成与Gate通过 |
| 异常回退 | `exception_routes` | 异常及回退、失败回退路径、失败处理、异常诊断与回退 | 必填，记录根因/回退对象/影响范围 |
| 审核模式 | `review_mode` | 审核、复核、审批与Gate、审批或放行 | T03必须显式配置 |
| 版本规则 | `versioning` | 版本规则、版本和记录、公共追踪字段、S07统一元数据 | 必填，允许继承S07公共元数据 |
| 下游接口 | `downstream_refs` | 向下游交接、交给、下游引用 | 必填 |

## 3. 审核模式

- `SELF_CHECK`：执行人自检，适合低风险中间任务；不能替代正式Gate或客户批准。
- `PEER_REVIEW`：同伴/另一职责复核，适合影响下游的中风险成果。
- `INHERIT_STAGE_GATE`：不为中间步骤单设Gate，由阶段准出Gate统一审核；步骤成果仍须有完成证据。
- `CLIENT_APPROVAL`：客户/品牌/产品权利人明确批准；仅在真实项目且其具有相应权限时使用。
- `EXTERNAL_EXPERT_REVIEW`：涉及专业法律、医疗、金融、技术等高风险事实时，按项目法域和行业要求配置适格审查。

个人创作者可兼任执行和内部复核角色，但必须如实记录。客户批准、产品权利人授权及依法需要的专业审查不得由AI或制作人冒签。

## 4. 公共元数据

每个步骤实例及成果至少关联：`project_id,step_instance_id,step_id,artifact_id,artifact_type,version,status,owner,reviewer,input_refs,source_refs,created_at,updated_at,review_log,rights_status,risk_status,change_request_id`。媒体文件增加`file_hash`；Gate记录增加`gate_id,scope_ids,reviewed_artifact_ids,reviewed_versions,reviewed_hashes,decision,findings,required_actions,approver,approval_evidence,reviewed_at,validity_conditions`。

## 5. 状态分离

任务状态、成果状态、Gate决策、媒体QA状态、交付状态、证据状态、权利状态和投放数据状态分别维护；不得把`DONE`等同`PASS`，也不得把媒体`QA_PASS`等同`G8_APPROVED`。

## 6. T03模板最小集合

1. 项目Brief与需求澄清模板。
2. 品牌/产品事实与宣称证据台账。
3. 策略与创意决策模板。
4. Script Master与Beat台账。
5. Director Bible与视觉约束模板。
6. 分镜主表、Shot–Beat映射与Animatic审查表。
7. Asset Register与Shot–Asset映射。
8. Production Task、Prompt、Attempt、Take及G7 QA日志。
9. 后期工程、Master Candidate及版本矩阵。
10. P10逐Variant QA/G8审批/交付清单。
11. P11数据、成本、问题复盘与改进登记。
12. Change Request、Issue、Gate Record和项目总控看板。
