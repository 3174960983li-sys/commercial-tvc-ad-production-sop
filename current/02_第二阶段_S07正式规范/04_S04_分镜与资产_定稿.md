## 0｜S04全局职责、准入及工序边界

### 0.1 分工边界

| 层级 | 本层主要决策 | 正式输出 | 明确不得代替 |
|---|---|---|---|
| P4（上游） | 哪些内容、信息、旁白出现在何时 | `script_id`、`beat_id`、品牌/宣称引用 | 逐镜`shot_id`和镜头机位 |
| P5（上游） | 导演意图、视觉/声音/摄影规则 | `director_rule_id`及Director Bible | 已锁定的正式分镜和正式资产 |
| **P6** | 各内容节拍用哪些镜头表达、如何时序衔接和预演 | `shot_id`、镜头表、起落幅、Animatic、镜头需求单 | 擅自更改批准的传播内容；批量生产正式商品资产 |
| **P7** | 为获准镜头提供哪些正式资产、版本和制作路线 | `asset_id`、资产母版、场景母版、Shot–Asset映射及生产方案 | 自主改变脚本、镜头、品牌事实；正式批量镜头生成 |
| P8（下游） | 按镜头与批准资产生成/拍摄/制作可剪接的视频素材 | `take_id`、生成记录、镜头母文件 | 私下改写资产不可变项、广告宣称、G5/G6锁定条件 |

### 0.2 进入与退出

- P6准入：G4通过，Script Master和Director Bible均有批准版本，当前交付矩阵（时长/画幅/语言/平台）可读取；P6准出G5。
- P7准入：G5通过，镜头需求清单已冻结并标记尚待制作资产；P7准出G6。P6预演期间可使用明确标为`PROXY`/`CONCEPT_REFERENCE`的临时参考，但不视作P7已批准资产。
- P7中若发现不可实现或高成本的镜头，先登记风险并向P6提交变更建议；G5旧版不能被新稿静默覆盖。
- 交付内不默认固定画幅、时长、帧率、制作模型。技术基础值由P0已批准的交付版本与P7-08生产配置决定。

### 0.3 角色与审核权限

| 职责 | 个人工作室执行方式 | 小团队执行方式 | 必要批准 |
|---|---|---|---|
| 镜头拆解/节奏/Animatic | 导演兼分镜师 | 导演＋分镜/剪辑 | 项目导演、创意负责人；客户要求时客户审批 |
| 产品/品牌基准 | 资产设计者参照批准原件 | 产品资产组＋品牌管理 | 品牌/产品有权负责人，不能以设计者自证替代 |
| 人物/场景/道具 | 一人多岗并留审查记录 | 人物、场景、道具岗位协作 | 导演/美术负责人及权利责任人 |
| 生产方案与G6 | AI制作负责人兼制片 | 技术/制片＋导演 | 项目授权审批人；阻断风险须闭环 |

个人项目可自审艺术与技术结果，但不得伪造客户认可或版权许可；模拟/作品集项目必须标识为`SIMULATED_BRIEF`。

### 0.4 标识与状态字典

| 对象 | 示例 | 唯一性及规则 |
|---|---|---|
| 内容节拍 | `AD001_B003` | P4生成；P6不得重编号 |
| 导演规则 | `AD001_DR007` | P5生成；P6/P7只能引用 |
| 分镜镜头 | `AD001_SH012` | **P6首次生成**；删镜保留ID及`RETIRED`，新镜用新号，编号不代表剪辑顺序 |
| 空间母版 | `AD001_SP002` | 指向统一空间结构与锚点；P7完善版本 |
| 角色/产品/道具 | `AD001_SUB004` | 表示叙事/商业主体的逻辑身份，不等同于某张图片 |
| 正式资产 | `AD001_AST023` | P7创建，绑定类别、母版与来源/权限 |
| 资产变体 | `AD001_AST023_V03` | 区分视角/服装/状态/渠道，不重写已锁定资产 |
| 镜头生成素材 | `AD001_SH012_TK004` | P8生成，引用固定`shot_id`与相关`asset_id` |
| 变更单 | `AD001_CR008` | 所有已锁定版本的改动必须关联CR |

- 核心文档状态：`DRAFT` → `IN_REVIEW` → `APPROVED` → `LOCKED`，`RETIRED`表示逻辑对象废弃，`SUPERSEDED`表示版本被新批准版继承；仅许可的Gate批准才可锁定。
- 预演素材状态：`PROXY`、`CONCEPT_REFERENCE`、`LICENSED_TEST`、`APPROVED_ASSET`严格区分，不得把网上视觉参考当成商用授权。
- 单镜状态：`ACTIVE` / `SPLIT_FROM` / `MERGED_FROM` / `RETIRED`；删除和重排不抹掉溯源。
- S00通用文档元数据必需：`project_id/artifact_id/stage_id/step_id/version/status/owner/reviewer/input_refs/source_refs/review_log/rights_status/risk_status/created_at/updated_at/change_request_id`（按需）。

### 0.5 共同遵守的不可变约束

**商业**：已批准的品牌名称、产品型号/外观、卖点宣称、CTA、目标受众、法务限制。  
**视听**：已批准的关键节拍、导演视觉规则、产品展示主次、核心品牌识别。  
**连续性**：人物身份和服装状态、产品部件/包装文字、道具持握、场景空间锚点、屏幕方向、动作起末态。  
**权利**：使用的产品图、肖像/声音、音乐、字体、素材和参考的使用许可状态。  
**生产**：镜头、资产、take与审核版本可相互追溯，未经批准不能把试验方案作为生产基准。

## 1｜P6 分镜设计与动态预演（11项）

**准入：** G4 PASS且P4/P5脚本与导演主版有效。  
**准出：** G5 PASS；`shotlist_version`、`animatic_version`、`shot_requirement_list`同步锁定。  
**成功定义：** 广告中全部必需信息都有对应镜头；镜头可读、可剪、可执行、可追踪，正式生产前即可发现主要时间与连续性问题。

### P6-01｜广告镜头结构划分

| S00规范字段 | 正式要求 |
|---|---|
| 业务目的 | 将P4内容节拍及P5导演任务转成可拍摄的镜头组与剪辑顺序候选；允许一节拍多镜、跨节拍镜头。 |
| 适用性 | **强制；全部广告** |
| 输入与证据 | G4批准Script Master、Director Bible、`beat_id`与时长/版本要求 |
| 职责与边界 | 导演/分镜负责人划分视觉信息单位；此时镜头数量可调整，但不得新增未批准的商业事件 |
| 输出与字段 | 《镜头结构草案》：`shot_id`、`sequence_order`、`beat_refs`、镜头职责、候选起止、理由、关键待核问题 |
| 完成判定 | 每个必须传播的节拍都有计划承载镜头；无未授权改写；拆/合镜都能追溯原节拍；镜头ID唯一 |
| 审批与Gate | 导演初审；G5最终核验 |
| 错误与回退 | 缺少必需传播内容→P4；导演要求矛盾→P5；单纯镜头拆分不合理→P6-01 |
| 版本与记录 | 新增镜头新ID；废弃镜头标`RETIRED`；镜头顺序和ID分别管理 |

### P6-02｜镜头功能与信息分配

| S00规范字段 | 正式要求 |
|---|---|
| 业务目的 | 规定每镜在观看、信息、产品、品牌及节奏方面的不可替代任务。 |
| 适用性 | **强制；全部广告** |
| 输入与证据 | P6-01候选镜头、P2主信息、P4内容节拍/文案/品牌映射表 |
| 职责与边界 | 分镜师逐镜标记主任务和次任务；避免重复炫技，允许必要的情绪与转场镜头 |
| 输出与字段 | 《镜头功能矩阵》：`shot_id`、`communication_job`、`visual_focus`、`brand_presence`、`claim_refs`、`copy_refs`、`beat_refs`、`must_keep` |
| 完成判定 | 所有关键商业信息可从镜头反向追到`beat_id/claim_id`；冗余镜头有目的；删镜不会造成主信息空缺 |
| 审批与Gate | 导演＋策略/创意审核；G5审查信息覆盖 |
| 错误与回退 | 信息目标错→P2/P4；分配重复→本步骤；品牌策略缺口→P4-06 |
| 版本与记录 | 记录每镜主传播任务及变化，更新覆盖率矩阵 |

### P6-03｜景别与机位设计

| S00规范字段 | 正式要求 |
|---|---|
| 业务目的 | 用可执行的摄影空间定义观众从哪里、以多大尺度观察产品与动作。 |
| 适用性 | **强制；静态/图形广告也需规定虚拟取景关系** |
| 输入与证据 | P5摄影原则、`space_id`、P6-02镜头目标、画幅/安全区要求 |
| 职责与边界 | 摄影/分镜明确景别、视角、相机方向、主体尺度、画面层次和读图优先级；不在此生产正式场景 |
| 输出与字段 | 《机位构图卡》：`shot_id`、`camera_position_id`、`shot_scale`、`view_axis`、起幅构图、主体位置、留白/安全区、多画幅风险 |
| 完成判定 | 每镜有可重复描述的机位和主体关系；核心信息可辨；需要反打的方向与空间锚点一致；镜头间变机位有依据 |
| 审批与Gate | 导演/摄影审查；G5可视化核验 |
| 错误与回退 | 空间不确定→P5-06/P7-04；选错景别或越轴→P6-03；画幅设计原则错→P5-04 |
| 版本与记录 | 保留机位编号、轴线方向和改动原因；异画幅可另建构图变体 |

### P6-04｜摄影机运动设计

| S00规范字段 | 正式要求 |
|---|---|
| 业务目的 | 为必要的信息揭示、情绪推进与商品展示规定具有起终状态的机位运动。 |
| 适用性 | **强制；允许镜头明确选择固定机位** |
| 输入与证据 | P5运动风格、P6-03构图、镜头时长预算、产能/技术风险 |
| 职责与边界 | 规定固定/移动、运动路径、速度变化、起止机位、主体相对位置与可行性，不以无目的运动代替内容 |
| 输出与字段 | 《镜头运动定义》：`shot_id`、`motion_type`、`start_camera_state`、`end_camera_state`、`movement_purpose`、风险等级、替代选项 |
| 完成判定 | 起落幅可衔接、主体不丢失、运动服务镜头任务；复杂运动有草稿验证方案；固定镜头明确标注 |
| 审批与Gate | 导演/摄影＋制作可行性评审；G5 |
| 错误与回退 | 运动与画面不可同时实现→本步骤/ P6-05；违反品牌风格→P5-04；生成失败→P8 |
| 版本与记录 | 记录运动路径版本和转场接口，变动同步更新首尾态 |

### P6-05｜主体动作与调度设计

| S00规范字段 | 正式要求 |
|---|---|
| 业务目的 | 明确人物、产品、道具、环境在镜内的可见行动及其空间/动作连续性。 |
| 适用性 | **强制；无主体动作则须说明静态状态** |
| 输入与证据 | P4事件与台词、P5表演/空间规则、P6-03/04 |
| 职责与边界 | 逐镜描述有明确姓名/主体ID的动作、位置、接触、方向、时序、初末状态；不随意添加情节 |
| 输出与字段 | 《主体调度与状态表》：`shot_id`、`subject_ids`、`space_id`、`initial_state`、`action_phases`、`terminal_state`、触点/屏幕方向/表演重点 |
| 完成判定 | 关键动作由明确主体完成；开合/拿放/转身/液体状态不自相矛盾；邻接镜可连续承接，无无意的动作重演 |
| 审批与Gate | 导演＋动作/场景/资产负责人核对；G5 |
| 错误与回退 | 脚本行动不成立→P4；调度方向不清→P6-05；空间固定点错误→P5-06/P7-04 |
| 版本与记录 | 初末态变化保留状态快照；影响邻接镜头的均列入影响单 |

### P6-06｜产品展示镜头设计

| S00规范字段 | 正式要求 |
|---|---|
| 业务目的 | 确保广告中的产品结构、可识别度、合法宣称和商业价值被有效可视化。 |
| 适用性 | **条件强制：出现实物/包装/功能演示的广告；纯品牌抽象创意按N/A写明品牌识别方案** |
| 输入与证据 | 品牌VI、官方产品图/型号、已核实`claim_id`、P4产品/卖点映射 |
| 职责与边界 | 分镜/美术定义产品可见面、尺度、朝向、关键细节、文字和功能演示限制；不依赖模型幻觉产出未获批功能 |
| 输出与字段 | 《产品展示镜头卡》：`shot_id`、`product_id`、`approved_reference`、`required_visible_parts`、`packaging_text_ref`、`claim_refs`、英雄画面要求、风险 |
| 完成判定 | 产品可被识别且不改变实物或批准设计；Logo、包装文字和型号有校验方案；事实演示与证据一致 |
| 审批与Gate | 品牌/产品负责人＋导演/分镜审核；G5检查任务，G6确认真实资产 |
| 错误与回退 | 事实不符→P1；核心卖点错误→P2/P4；构图遮挡→P6-03/06；资产错误→P7-01/02 |
| 版本与记录 | 镜头与商品母版/`claim_id`双向关联；变更产品型号触发上游审批 |

### P6-07｜镜头衔接与转场设计

| S00规范字段 | 正式要求 |
|---|---|
| 业务目的 | 保证相邻镜头以及独立生成片段之间信息、空间、运动和声音连续。 |
| 适用性 | **强制；即使一个镜头也需规定首尾与品牌收尾接口** |
| 输入与证据 | P6-03～06起落幅、P4台词与Cue、P5空间/声音规则 |
| 职责与边界 | 逐对审查末态/首态、轴线、屏幕方向、人物与商品位置、运动接续、转场类型和音频切点 |
| 输出与字段 | 《镜间接口表》：`from_shot_id`、`to_shot_id`、`cut_type`、末态/首态、动作相位、方向、声桥、连续性风险、审核状态 |
| 完成判定 | 逐对相邻镜头都有接口定义；不存在无意的跳轴、道具跳位、身体方向或剧情时间矛盾；跨独立生成片段默认优先采用明确变化的机位角度来降低穿帮，例外须说明 |
| 审批与Gate | 导演/剪辑/分镜联合审查；G5 |
| 错误与回退 | 相邻关系错误→P6-03/05/07；结构性节奏问题→P6-01；正式资产不支持→P7回馈P6 |
| 版本与记录 | 每次重排自动重建所有受影响邻接对；不得只改某镜、不更新相邻镜 |

### P6-08｜广告分镜表编制

| S00规范字段 | 正式要求 |
|---|---|
| 业务目的 | 将批准的分镜决策统一成可阅读、可审核、可被P7/P8调用的结构化主表。 |
| 适用性 | **强制；全部广告** |
| 输入与证据 | P6-01～07、P4品牌/台词、P5视觉与声音规则 |
| 职责与边界 | 用可读核心八栏展示镜头；复杂广告专项要求转入关联表，不允许把所有技术字段挤成不可读巨表 |
| 输出与字段 | 《分镜主表》及关联索引：`shot_id/order/t_in/t_out/task/framing/scene_state/subject_action/camera_audio/out_to_next`和`beat_refs/claim_refs` |

### P6-09｜分镜图制作

## 3｜跨阶段数据结构与交付规范

### 3.1 ID链路（支持一对多和多对多）

```text
project_id
 ├─ script_id@version
 │   └─ beat_id (一个内容节拍可关联若干镜头)
 ├─ director_rule_id@version (一个规则可以覆盖多镜头)
 ├─ shot_id@shotlist_version (一个镜头可关联多个beat_id)
 │   ├─ shot_state_id / adjacent_cut_id
 │   ├─ space_id + space_version
 │   ├─ subject_id + subject_state_id
 │   ├─ asset_id + asset_variant_id (多对多)
 │   └─ P8: take_id@version (不在S04制作)
 └─ gate_id@reviewed_versions (G4、G5、G6)
```

- 镜头编号按首次生成时分配，不因播放顺序重排而修改；排序字段独立为`sequence_order`。
- `beat_shot_map`必须保存**镜头覆盖节拍的区间与功能**；一镜跨节拍和一节拍多镜均合法。
- 演示性零件`brand_asset_id`和`asset_id`相互引用但不混同，官方商标应保留可审计源文件。
- 分镜图册、Animatic均必须指出使用的是**概念代理**还是**正式已批准资产**。

### 3.2 主分镜表：八列阅读层 + 机器可追溯关联层

为兼容用户已建立的《镜头语言设计 Skill V1.5》八列分镜与场景状态规范，**人类审片用的阅读主表**固定八列；不要把所有审核、法律、资产、生成技术字段挤入同一张表：

| 列 | 分镜阅读字段 | 要求 |
|---|---|---|
| 1 | 镜号／时长／累计时间 | 稳定`shot_id`、镜头在片内序号、起止时间（总时长自洽） |
| 2 | 镜头任务 | 观看任务与主要商业传播作用，简明明确 |
| 3 | 起幅与构图 | 景别、机位、角度、主体位置、主要可见元素 |
| 4 | 场景状态 | 时间、地点、内外景/抽象空间、`space_id`与状态 |
| 5 | 角色表演与场景动态 | 明确角色或产品主体名称、镜内动作及环境交互 |
| 6 | 摄影机与光学 | 固定/推拉摇移跟等及运动路径、对焦/景深等必要信息 |
| 7 | 声音与对白 | 已批准台词、广告旁白、音效Cue、静音适配需求 |
| 8 | 落幅、切点与承接 | 当前镜头结束状态、下一镜起幅、声画切接约束 |

**并行的商业关联表**必须至少含：`shot_id`、`sequence_order`、`beat_refs`、`claim_refs`、`copy_refs`、`product_id`、`brand_asset_refs`、`must_keep`、`director_rule_refs`、`asset_refs`、`variant_refs`、`rights_status`、`risk_status`。

**多版本阅读原则**：每支独立广告片/长度/渠道版本用一张独立分镜主表，不混成跨版本的巨大总表。跨版本一致性通过ID链及变更表保持；每镜可因画幅重新设构图，不能自动裁切导致品牌文字/产品关键部件缺失。

### 3.3 镜头初末态和切点接口

| 字段 | 含义 | 检查重点 |
|---|---|---|
| `initial_state` | 进入本镜头瞬间的人物、产品、场景状态 | 人物站位、产品朝向、持握手、开合状态、光影 |
| `action_phases` | 有先后顺序的镜内动作阶段 | 不用模糊指代；单镜可实际执行 |
| `terminal_state` | 退出本镜头瞬间的状态 | 可明确交给下一镜，不无缘由状态跳跃 |
| `screen_direction` | 运动/视线在银幕内方向 | 正反打、轴线、物体移动方向 |
| `cut_type` | 硬切、匹配剪辑、叠化、音桥等 | 不同剪辑方式有各自时长与状态约束 |
| `camera_view_change` | 与上一独立AI视频段的机位变化及目的 | 默认规避无意义相同机位跨段续拍；保留有明确设计依据的匹配延续例外 |
| `sound_overlap` | 声桥/旁白跨镜保留范围 | 不重播台词，不截断主要信息 |

**注意**：连续性不能机械地等于“每镜必须景别跳级”。产品旋转演示、匹配剪辑、视觉音乐化广告可能需要连续尺度或特殊机位；例外由导演批准并验证效果。

### 3.4 时间轴核算标准

1. P6使用统一项目时间基准；视频时间以整数帧作为最终验算单位，记录实际`fps_num/fps_den`（例如25/1或30000/1001）。
2. 线性硬切版：每个镜头的剪辑区间统一半开区间`[in_frame, out_frame)`；要求`out(i)=in(i+1)`，总帧数等于母版总帧数。
3. 叠化/重叠声画：分别保留素材源时码和**最终时间轴占用区间**；不能简单把所有原素材长度相加冒充成片时长。
4. 同一节拍可被多个镜头分担；计算覆盖的是节拍的*信息任务及最终占用时长*，不要求每节拍恰好一镜。
5. 配音/字幕的可读时长应在动态预演真实检查；不能以总时长等于30秒推断观众一定能读完。
6. 未确定目标技术交付时，时长可以用秒设计，但要标`PROVISIONAL`，G5应以批准的时基形成能检查的时间轴。跨渠道变体分别核算。

### 3.6 资产状态、授权与版本

- `asset_role`: `PRODUCT` / `BRAND` / `CHARACTER` / `ENVIRONMENT` / `PROP` / `EFFECT` / `AUDIO_REFERENCE`。
- `asset_origin`: `CLIENT_OFFICIAL` / `LICENSED_SOURCE` / `ORIGINAL_AI` / `ORIGINAL_LIVE` / `ORIGINAL_CG` / `CONCEPT_REFERENCE`；原始来源**不是**版权结论。
- `rights_status`: `VERIFIED` / `RESTRICTED` / `PENDING` / `PROHIBITED`；任何需在正式商业作品使用却为`PENDING/PROHIBITED`的关键素材不得越过G6。
- `asset_lifecycle`: `DRAFT` / `REVIEW` / `APPROVED` / `LOCKED` / `SUPERSEDED` / `RETIRED`。
- `asset_state_id`: 处理同一商品不同开合、瓶液量、服装、损伤、天气、场景陈设、道具持握等状态；**状态变化不是新主体**，与主体母版形成父子关系。
- P7授权审核仅确认现有证据和风险状态，P10仍需对实际最终使用情况复核；本SOP不是法律意见。

### 3.7 AI与实拍/CG混合素材交接

P7-08在生产方案中约定：`shot_id`、目标画幅与安全区、目标时长、实际时基、分辨率与编码候选、色彩管理约定、音轨/字幕交接方式、镜头起末态、产品主版本、参考图权益、责任人员、审核和日志字段。

- 实拍镜头须能引用同一`shot_id`、有权产品母版及场景方位；实拍勘景/实物形态变更需更新资产或变更单。
- CG镜头须在产品尺寸、运动路径、灯光方向、材质和色彩目标上遵守同一镜头接口。
- AI镜头应在草稿优先验证大运动、角色与产品一致性，正式视频生成由P8执行并通过G7a/G7b。
- 产品Logo/包装小字、法定标签、价格等精确文字优先保留可编辑的核实文本图层，由合成阶段进行逐字复核；仅由生成模型自由生成的字样不能当作核实版本。

## 4｜镜头变更、拆合、删除及对照审阅

### 4.1 修改类型与操作许可

| 变更类型 | 可以修改 | 必须保留 | 是否自动重审G5 |
|---|---|---|---|
| `FORMAT_ONLY` | 列顺序、显示格式、文字排版 | 镜号、实际内容、景别、时长、动作、台词、切点 | 否；需核对格式无语义改动 |
| `LOCAL_REVISE` | 明确范围内的镜头/动作/转场 | 其他镜头及已批准信息 | 若已锁定且影响时间、衔接或商业信息，则是 |
| `ADD_SHOT` | 在适当位置加新镜并再分配时长 | 原镜头ID及变更来源 | 已锁定时是 |
| `DELETE_SHOT` | 将无功能镜设为RETIRED并重排 | 旧镜内容及退役原因 | 已锁定时是 |
| `SPLIT_SHOT` | 由一镜拆成两镜或多镜 | 父镜ID、拆分关系、动作分段 | 已锁定时是 |
| `MERGE_SHOTS` | 合并连续且可执行的镜头 | 全部来源镜号与信息功能 | 已锁定时是 |
| `REORDER_SHOTS` | 调整时间顺序 | 原顺序、剪辑关联与信息路径 | 已锁定时是 |
| `UPSTREAM_CHANGE` | 改商业信息、卖点、脚本或导演核心规则 | M02批准与全部受影响版本 | 回G4及必要更早Gate后再重审G5 |

**重要：** 新稿不得直接覆盖旧稿。审阅表推荐左右并列显示“原批准分镜”与“修订建议分镜”，使用醒目标记说明改动位置和理由；被删除镜头保留原文并标记退役。表格独立按每条广告和每个交付版本组织。拆合镜可改变镜头数量，不以原稿镜数为约束，但每个变化必须满足已批准脚本。

### 4.2 变更影响自动核对

- 变更镜头总时长 → 重算片长、全部后续镜头时码、字幕/旁白/音乐Cue及交付变体。
- 变更机位/角度/动作初末态 → 重新核对上一镜和下一镜的空间、动作与音频接口。
- 变更产品可见面 → 核查`asset_id`的对应视角、包装文案、反射/材质限制和品牌审批。
- 变更角色服装/商品状态 → 检查主体状态链和全部复用镜头。
- 变更场景结构 → 检查所有复用该空间母版的机位图、主反打及场景状态。
- 变更Logo、上屏文字或产品规格 → 先检查P1/P4批准链和全部使用该内容的镜头/资产/成片版本。

### 4.3 示例：拆分镜头（仅验证系统关系）

原稿：`SH012` 6秒，商品旋转并出现包装文字。  
修订：`SH012`标记`RETIRED`；新增`SH027` 3秒（产品旋转至正面）＋`SH028` 3秒（锁定包装正面特写），`parent_shot_ids=[SH012]`。  
检查：时间轴仍6秒、两镜品牌文字不变、商品朝向相接、`SH028`新增正面包装资产需求、相邻镜的切接重新评审。  
审批：若原稿G5已通过，提交CR并生成新的G5批准版本；若尚未通过，按普通候选版迭代但仍保留版本历史。

## 5｜G5分镜与预演Gate、G6资产与生产Gate

### 5.1 G5放行前检查

| 维度 | PASS最低要求 | 阻断示例 |
|---|---|---|
| 内容覆盖 | 全部关键`beat_id`均被合格镜头覆盖 | 核心卖点/品牌结尾消失 |
| 镜头结构 | 每镜有目的且能清楚识别 | 重要镜头无法表达具体信息 |
| 时长与节奏 | 时间轴闭合，旁白与重要上屏信息可读 | 总时长错误或CTA无可读时间 |
| 构图与动作 | 起幅/落幅/调度/机位能执行 | 明显跳轴、动作重复或不可能运动 |
| 产品表现 | 要求出现的产品形态/品牌信息有承载镜头 | 商品关键部位无法显示、虚构功能 |
| 声画一致 | 语音/Cue有对应时段并保留必要静音策略 | 声音信息与画面冲突、重要信息无法理解 |
| 变体适配 | 目标平台/时长/比例有镜头保留和重构方案 | 跨比例直接裁掉Logo/CTA |
| 预演证据 | Animatic版本可复核，代理素材状态清楚 | 将无权参考当成已批准商业画面 |

**G5最低记录：** `project_id/gate_id/shotlist_version/animatic_version/script_version/director_version/reviewer/decision/critical_findings/conditions/owner/approval_evidence/date`。

### 5.2 G6放行前检查

| 维度 | PASS最低要求 | 阻断示例 |
|---|---|---|
| 产品与包装 | 商品外观和关键包装文案校验可追溯 | 形状/色彩/Logo/产品型号失真 |
| 人物与场景 | 主体身份、服装状态和空间锚点稳定 | 人脸漂移、主反打空间自相矛盾 |
| 资产映射 | 每个必须制作的ACTIVE镜头有正确资产和状态 | 缺失必要英雄产品资产或错镜引用 |
| 权利及合规 | 正式商用素材/声音/肖像使用范围明确 | 未获授权的必须素材被列为可商用 |
| 技术与成本 | 制作模式、草稿计划、备选路线和预算风险明确 | 核心镜头无可行路径且未处理 |
| 跨阶段一致性 | G5镜头版与G6资产需求版对应 | 使用退役镜头或错误脚本资产 |

**G6最低记录：** `project_id/gate_id/approved_shotlist_version/asset_manifest_version/shot_asset_map_version/production_plan_version/rights_review_ref/reviewer/decision/open_findings/approval_evidence/date`。

**共同决策状态：** `PASS`、`CONDITIONAL`、`REWORK`、`HOLD`。阻断性/重大缺陷不允许靠总体打分抵消。`CONDITIONAL`仅用于不妨碍下一阶段且具责任人、期限和关闭检查的低风险缺口，不适用于产品失实、商用授权缺失等硬风险。

### 5.3 回退/重审路径

| 发现的问题 | 首先查找根因 | 返回位置 | Gate变化 |
|---|---|---|---|
| 品牌露出或卖点丢失 | 设计镜头未覆盖？脚本本身遗漏？ | P6-02或P4-06 | G5；若源于脚本需G4 |
| 视觉风格偏离品牌 | 镜头个案还是导演整体规则？ | P6-03/04或P5-02/04 | G5或G4+G5 |
| 包装/Logo错误 | 模型图版错误、官方资产错或脚本文字错？ | P7-02、P1、P4 | G6及受影响上游Gate |
| 空间主反打矛盾 | 机位违反母版还是母版本身矛盾？ | P6-03/P7-04或P5-06 | G5/G6，必要G4 |
| 动作不连续 | 镜间切点还是商品/道具状态错误？ | P6-05/07或P7-05 | G5/G6及相关下游 |
| AI无法可靠生成复杂镜头 | 执行困难还是设计不适合？ | P8草稿或P6-04/P7-08 | G7a；方案改变重审G5/G6 |
| 成本超预算 | 工具/生成轮次还是创意范围问题？ | P7-08/M06或P0/P3 | G6，必要上游Gate |
| 有权使用范围不清 | 素材许可、人物授权或产品权属缺失 | M08与P7对应资产 | G6 HOLD，必要G0/G4 |

**再审批原则**：不是每个局部错误都要全链重跑；只重审受影响的Gate和依赖对象。但对于已锁定阶段，先通过M02生成新版本与变更证据。

## 6｜按广告类型与制作路线的差异标准

| 类型/路线 | P6分镜重点 | P7资产重点 | 特有检查 |
|---|---|---|---|
| 品牌形象/TVC | 品牌识别、情绪渐进、品牌收尾与节奏 | 品牌VI、空间/服装/色彩一致性 | 视觉好看但无品牌记忆的风险 |
| 产品展示/美妆 | 英雄产品镜、使用/材质镜、包装可读镜 | 真实商品外观、颜色、商标/标签、液体与材质 | 包装文字/颜色/功效虚构 |
| 科技产品/功能广告 | 功能演示因果、可见交互和证据链 | 官方硬件接口/按钮/屏幕UI/真实功能来源 | AI创造不存在的接口或功能 |
| 创意概念 | 视觉隐喻可理解、从创意回到品牌 | 概念元素与品牌资产统一 | 创意与产品脱节 |
| 信息流/转化 | 关键信息前置、静音可理解、CTA适配 | 多画幅品牌文字安全区、渠道文字层 | 一键裁切遮掉CTA或关键信息 |
| 活动/发布/多语种 | 日期/产品/价格/地域版本的镜头占位 | 可编辑的日期/语言/价格/字体素材 | 旧活动日期或错误语言版本 |
| AI+实拍+CG混合 | 明确素材源衔接的空间、光向与镜位 | 产品母版、实拍参考、CG比例/色彩对接 | 运动尺度、色彩和权利来源不统一 |

**广告类型可叠加**。不因采用TVC、科技、转化等不同标签而跳过商业事实、权利和Gate要求。

## 7｜与现有导演/分镜/场景Skill的集成边界

本S04只是定义**商业项目的输入输出与验收合同**；现有《镜头语言设计 完整Skill V1.5》（`shot-language-design`）、《影视场景资产与反打设计 Skill V1.0》（`film-scene-spatial-design`）可作为实施时的专业模块。这里核对的是可读取的文档内容，**不表示已经把Skill安装到用户本地Codex环境，也不代表其当前运行版本必然相同**。

|---|---|---|---|

**两条重点继承原则**：

1. “重新设计”即从零设计新的候选资产；“局部修改/反打/状态变化”必须继承已有锁定母版，不得私自改变未授权的结构、比例、颜色或身份。
2. 相邻独立AI生成片段默认检查机位视角的合理变化，避免连续同机位带来的跨段细节跳变；但镜头转换必须首先满足叙事轴线和产品展示目的，不能为了变机位而造成跳轴或丢失信息。

### 8.1 可检验的接口不变量

- 每个`ACTIVE shot_id`至少有一个`beat_ref`或获批的声画/转场任务说明。
- 每个被标记为`MUST_KEEP`的内容节拍，至少由一个可用镜头承载，且广告主信息没有被可选镜头替换掉。
- 每个需要明确主体/场景的镜头，均可解析出`subject_id/space_id`及相应状态；不适用时显式`N/A`。
- 每个`asset_id`必须有唯一类别、来源、权利状态、生命周期与版本；`shot_asset_map`指向可找到的资产。
- 已批准`asset_id/version`无法被未获批版本静默覆盖；出现缺失引用时不能通过G6。
- 已锁定`script_version/director_version/shotlist_version/asset_manifest_version`在Gate表中能成组还原。
- 平台变体与主版本的品牌/事实一致性、素材安全区和时长各自通过核对。
