## 1. S00｜跨阶段统一标准
### 1.1 每项工作步骤的规范字段（适用于全部99项）
| 字段 | 必须说明的内容 |
|---|---|
| 步骤ID与名称 | 必须复用架构定稿中的P0-01至P11-07编号，不随意改名 |
| 业务目的 | 该步骤解决哪一个商业/导演/制作问题 |
| 适用性 | 强制/条件强制/可选；何种广告类型需要执行 |
| 输入与证据 | 上游已批准文件、客户提供材料、证据来源及版本 |
| 主要动作 | 活动边界与协作对象；第三阶段才写详细操作 |
| 输出与字段 | 交付物名称、必填字段、命名与关联ID |
| 完成判定 | 可验证的检查条件而非“足够优秀”等主观词 |
| 审批与Gate | 负责制作、负责批准、审批记录 |
| 失败与回退 | 错误类别、回退步骤、影响范围、重审条件 |
| 版本与记录 | 状态、版本、修改时间、责任人与变更单ID |

### 1.2 交付物通用元数据
`project_id`、`artifact_id`、`artifact_type`、`stage_id`、`step_id`、`version`、`status`、`owner`、`reviewer`、`created_at`、`updated_at`、`input_refs`、`source_refs`、`related_shot_ids`（适用时）、`review_log`、`rights_status`、`risk_status`、`change_request_id`（适用时）。

### 1.3 核心质量分类（不以总分抵消阻断）
| 级别 | 判定原则 | 处理方式 |
|---|---|---|
| BLOCKER | 产品/品牌事实失真、必要授权缺失、违法或无法通过渠道硬性要求、交付不可播放 | 停止放行，定位根因并返工 |
| MAJOR | 核心信息不清、关键镜头错误、视觉一致性明显失控、KPI口径缺失 | 返工后复核 |
| MINOR | 不影响商业信息的局部细节、非关键声音/动画瑕疵 | 登记并视交付要求修正 |
| SUGGESTION | 审美或效率进一步提升 | 可进入优化清单 |
不默认采用“90分商业可交付”的绝对结论：评分仅用于内部排序，最终必须通过所有必需Gate与客户验收。

### 1.4 决策、状态与证据要求
- 所有客户批准及重要变更须有可追溯记录（签批文件、确认邮件、审片记录等）。
- 事实陈述标记为 `VERIFIED`、`CLIENT-SUPPLIED UNVERIFIED`、`TO VERIFY`、`REJECTED`；未核实不得写成已经证实。
- 对广告宣称采用独立claim_id；上屏文案必须关联批准过的claim_id或标记为非事实性创意表达。
- 每个镜头编号必须稳定；新增镜头用新ID，删除镜头保留作废记录，禁止复用已使用过的ID。
- `LOCKED`基线不可原地覆盖；修改生成新版本，并注明受影响阶段和重新放行的Gate。
- 作品集模拟项目仍必须明确虚构品牌或使用权限；模拟数据、演示产品效果不得冒充真实商用证据。

### 1.5 统一技术接口（用于AI/实拍/CG混合）
每个视频素材至少记录：`shot_id`、`take_id`、`source_mode`（AI/Live/CG/Hybrid）、`file_name`、`duration`、`fps`、`dimensions`、`aspect_ratio`、`color_space`、`audio_present`、`source_assets`、`generator_or_camera`、`license_status`、`qa_status`。
禁止在没有投放渠道具体要求的情况下冻结全项目唯一分辨率、码率或帧率；技术交付规格应以广告主、投放渠道、发行商与设备要求为准。VAST属于视频广告投放/播放器数据接口，不等同于成片编码标准。

### 1.6 Gate审查记录模板
`gate_id｜reviewed_version｜reviewed_by｜review_date｜decision(PASS/CONDITIONAL/REWORK/HOLD)｜blocking_findings｜open_actions｜owner｜recheck_due｜approval_evidence`

## 2. S01｜P0 立项标准
**阶段目的：**形成完整、可批准的项目需求基线，防止边界不明导致后续返工。
**准入：**收到客户需求或作品集模拟Brief；**准出Gate：**G0。
| 工作步骤 | 规定的最小输出 | 步骤完成判定 |
|---|---|---|
| P0-01 | 需求原文、联系人/批准人、沟通记录 | 所有关键需求能回溯到提出者 |
| P0-02 | 多轴广告类型与投放渠道标签 | 记录主商业目标和至少一个交付渠道 |
| P0-03 | 结构化广告Brief v01 | 必填字段完整；缺失项有责任人与状态 |
| P0-04 | 范围清单及排除项、母版/适配版目录 | 写明成片用途、版本数量及甲乙方责任 |
| P0-05 | 预算区间、时间节点、关键资源、风险表 | 估算假设明确，不把假设当已批准预算 |
| P0-06 | 项目ID、目录、负责人、G0审核记录 | 项目主数据可找到，达到启动条件 |

#### P0 输出文件：广告Brief（必填字段）
| 字段 | 说明 |
|---|---|
| project_id / 客户或模拟项目标识 | 项目唯一编号、真实客户还是作品集模拟 |
| 产品与品牌 | 官方名称、型号/版本、品牌识别文件链接 |
| primary_objective | 认知/考虑/转化/活动；如有次目标另列 |
| target_audience | 核心受众、地域和语言，不必强行用单一年龄段定义 |
| key_message | 客户希望用户记住的最核心一句信息 |
| verified_claims | 已批准的事实性卖点及证据引用 |
| CTA / landing | 期望行为、目的链接或备注暂无 |
| platforms / territories | 计划发布平台与投放地域 |
| deliverable_matrix | 时长、横/竖屏、语言、条数、需交付的工程/母版 |
| brand_constraints | Logo、安全区、禁用表现、调性、竞品回避等 |
| assets_and_rights | 产品图、音乐、字体、肖像和素材授权责任 |
| budget / schedule | 预算上限、评审节点、交付时间 |
| approval_authority | 客户或内部最终批准人 |
| unknowns_risks | 待确认事项、负责人、最晚确认节点 |

**G0阻断条件：**不明确广告目标或用途；不明确谁能批准；产品/品牌归属不明；无法判断是否有权使用必要素材；关键交付要求无法确认。

## 3. S01｜P1 品牌与产品研究标准
**阶段目的：**建立经过分级核实的事实、品牌规范和消费者假设集合。**准入：**G0通过。**准出：**G1。
| 工作步骤 | 规定的最小输出 | 步骤完成判定 |
|---|---|---|
| P1-01 | 品牌资料索引、定位声明、官方来源 | 品牌信息来源和有效版本可追溯 |
| P1-02 | Logo/VI/调性及禁用清单 | 已区分官方强制规范与分析者推断 |
| P1-03 | 规格/功能/成分/价格/适用条件事实台账 | 每条对外可用事实都有证据状态 |
| P1-04 | 卖点候选与主次清单 | 候选优势不自动等于可宣传承诺 |
| P1-05 | 竞品矩阵、典型广告链接、研究日期 | 实际来源和观测窗口明确 |
| P1-06 | 用户需求、疑虑与证据来源 | 事实数据和研究假设分栏 |
| P1-07 | 研究结论、风险和可用材料目录 | 所有未证实问题被登记并分派责任人 |

#### P1 输出文件：证据及宣称台账
必填列：`claim_id｜产品/版本｜拟表达内容｜类型(功能/性能/效果/价格/比较/品牌)｜来源｜证据日期｜适用市场｜适用范围与条件｜核验状态｜批准人｜禁止或限定措辞｜可用渠道`。
示例：`CLM-001｜某护肤品｜含有某成分｜成分｜经批准配方文件｜...｜VERIFIED｜...`。注意“含有成分”不能自动推导出某种临床效果。
**G1阻断条件：**核心产品事实无法识别；品牌官方资产混淆；必须依赖却无法证明的功能/效果宣称；证据来源不可追溯。

## 4. S02｜P2 商业策略与广告定位标准
**阶段目的：**将研究事实转化为可执行的传播目标与价值主张。**准入：**G1通过。**准出：**G2。
| 工作步骤 | 规定的最小输出 | 步骤完成判定 |
|---|---|---|
| P2-01 | 主商业目标、辅助目标和测量方案 | 主目标明确，不混写曝光与转化 |
| P2-02 | 主要/次要受众、渠道匹配理由 | 目标受众可被描述并找到接触场景 |
| P2-03 | 用户动机、痛点、顾虑、证据等级 | 洞察不是仅凭个人臆测 |
| P2-04 | 产品特征→可证实利益→消费者意义矩阵 | 每条功能性利益均关联claim_id |
| P2-05 | 单一主传播信息与优先级清单 | 能用一句话概括，次信息不抢主信息 |
| P2-06 | 渠道、创意任务、行动引导、测量指标 | CTA与主要商业目标相匹配 |
| P2-07 | 策略说明书和客户确认记录 | 商业目标与创意约束可直接传给P3 |

#### P2 输出文件：核心信息卡
必填字段：`primary_objective`、`audience`、`consumer_insight`、`value_proposition`、`single_minded_message`、`reason_to_believe`（证据ID）、`desired_response`、`CTA`、`channels`、`success_metrics`、`constraints`、`approver`。
评价指标必须定义**计算口径、观察窗口及是否可获得**。例如在投放端可得的情况下才评估CTR、CVR、CPA；品牌广告可采用完成率、品牌研究或主动搜索等。不得保证特定商业效果。
**G2阻断条件：**受众不清、主传播信息缺失、价值主张建立在未获证实事实、实际商业目标与行动引导冲突。

## 5. S02｜P3 广告创意策划标准
**阶段目的：**在既定策略下提出明确、差异化且可执行的创意表现。**准入：**G2通过。**准出：**G3。
| 工作步骤 | 规定的最小输出 | 步骤完成判定 |
|---|---|---|
| P3-01 | 至少一个可行创意方向及备选探索记录 | 方向与单一主信息有关联 |
| P3-02 | 一句话创意概念、逻辑、消费者感受 | 能说明创意为什么服务于策略 |
| P3-03 | 创意主题、主口号草案及限制 | 主题符合品牌语言且不过度承诺 |
| P3-04 | 核心视觉意象、风格参考和品牌植入位 | 参考素材用途和授权边界明确 |
| P3-05 | 叙事方式/时长结构/声音基本设想 | 可在目标时长与生产条件内实现 |
| P3-06 | Logo、产品、包装、CTA的预期露出逻辑 | 不出现观众看完仍无法识别品牌的结构漏洞 |
| P3-07 | 创意提案与批准版本、退选原因 | 保留版本选择的商业/制作理由 |

#### P3 输出文件：创意提案页
1. `concept_title`：概念名称；2. `big_idea`：一句话核心创意；3. `strategic_link`：如何服务P2主信息；4. `story_or_visual_mechanism`：具体叙事或视觉机制；5. `brand_role`：品牌和产品何时、如何出现；6. `emotional_effect`：希望产生的感受；7. `production_feasibility`：AI/实拍/CG可实现性与风险；8. `rights_and_claims_review`：权利/宣称风险；9. `client_decision`：批准/退选与理由。
**G3阻断条件：**创意与P2策略脱节、依赖无法授权的肖像/作品、误导性产品效果、目标时长内核心信息无法表达、无可执行制作路线。

## 9. P0–P3逐项独立规范（S07补齐，具有正式效力）

下列记录与上文原始“最小输出/完成判定”表共同生效；如果字段描述存在表面重复，优先采用具体步骤卡与跨阶段统一规则。第三阶段再进一步编制操作手册，不在此提前描述工具步骤。

### P0-01｜客户需求接收

| S00字段 | 正式标准 |
|---|---|

| 适用性 | 强制；全部广告项目。无法获得非关键资料时须声明缺失、适用范围和替代证据，不得伪造。 |

| 错误与回退 | 需求来源不清→P0-01重新确认；事实冲突→提交客户澄清；凡修改冻结资料须登记M02与影响对象。 |
| 版本与记录 | 保留原输入版本、检查结论、责任人、审批证据、变更号及前后差异；已锁定版本不原地覆盖。 |

### P0-03｜广告 Brief 信息整理

|---|---|
