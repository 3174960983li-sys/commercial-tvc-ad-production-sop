# S07｜跨阶段统一规则与冲突修订 V1.0

**状态：**第二阶段规范性附录，优先于各S00–S06文件中相互冲突的跨阶段术语与状态。第一阶段冻结的12阶段和99项步骤编号不变。

## R01｜优先级与适用范围

1. 本规范仅对跨阶段接口、状态、Gate、证据追踪和例外权限作统一定义；阶段内部的具体标准仍由原对应文件管辖。
2. 规则冲突的优先级：项目适用法律与渠道强制要求 > 获授权且不违法的客户已确认约束 > 第一阶段冻结架构 > 本S07统一规则 > S00–S06阶段标准 > 第三阶段操作教程/Skill默认值 > 模型经验性建议。此优先级**不允许**以合同替代法律或以公司内部约定免除必要授权。
3. 广告分镜不自动继承某短剧项目“单镜至少2秒、对白镜不超过6秒、0.5秒步进”等创作习惯；这些要求只有在本广告Brief明确采用且与平台/时基兼容时才成为可验证约束。具体镜头时长以传播目标、可读性、动作、剪辑与项目技术时基决定。
4. 所有客户/平台参数应以实际项目的渠道、地区、日期、已批准版本为准，SOP本身不保证固定时长、音量、编码、模型能力或广告效果。

## R02｜10个主Gate及G7子Gate

- 主Gate为`G0,G1,G2,G3,G4,G5,G6,G7,G8,G9`共10个；**G7为复合生产Gate**，拆为`G7a`（草稿可行性）与`G7b`（正式素材可用性）。未履行相应子Gate的镜头不能宣称“G7已通过”。
- `G4`联合审核P4脚本与P5导演方案；P4内部批准仅授予用于导演开发的资格。
- `G8`审核每个确定的`delivery_variant_id + file_hash + market + platform + rights_scope`，其通过只代表批准交付；`DELIVERED`与`CLIENT_ACCEPTED`为另两项可分别证明的事实。
- `G9`在P11正式启动后强制关闭；若没有启用P11，应记录`P11_NOT_ACTIVATED`及`G9_NOT_APPLICABLE`，不得称G9已经PASS。
- 每个Gate审查记录至少包含：`gate_id,scope_ids,reviewed_artifact_ids,reviewed_versions,reviewed_hashes,decision,findings,required_actions,owner,approver,approval_evidence,reviewed_at,validity_conditions`。

### 审核决策语义

| 决策 | 适用含义 | 能否进入下一阶段 |
|---|---|---|
| PASS | 全部必需检查完成，无阻断或重大未关闭问题 | 可以，但仅限批准的对象和版本 |
| CONDITIONAL | 仅剩不影响当前判断和下一动作安全性的轻微文书/非关键项，已有责任人与截止时间 | **仅在具体条件明确、不依赖未完成项时**允许部分推进；不得用于产品真实性、权利、主要技术/品牌/商业要求 |
| REWORK | 已发现需要重做/修改的内容缺陷 | 不可将受影响对象推进到下一个正式Gate |
| HOLD | 缺少必要资料、证据、批准人或外部前提 | 暂停受影响对象；不把未知视作不适用 |

- 不允许已知`BLOCKER`或未关闭`MAJOR`通过Gate；`WAIVED_WITH_APPROVAL`仅可用于按项目约定确实非关键、可依法豁免的缺陷，绝不豁免法定权利或事实性要求。
- `CONDITIONAL`产生的待办必须成为机器可追踪`condition_id`；未关条件若直接影响后续动作则该动作不得启动，正式G8必须复核所有关联未闭项。

## R03｜唯一ID与不变版本映射

| 对象 | ID规范 | 不变量 |
|---|---|---|
| 项目 | `project_id` | 不随客户反馈更改 |
| 内容节拍 | `beat_id` | 同一节拍在脚本版本中保持身份，实质拆合则新ID/映射 |
| 创作镜头 | `shot_id` | 导演意图的稳定身份；重新排序不改ID |
| 镜头在交付版中的使用 | `variant_segment_id` | 每一条成片时间线片段独立ID，关联shot、take和版本 |
| 视觉主体及状态 | `asset_id / asset_state_id` | 母版身份与开合、服装、场景状态分开 |
| 生产任务/尝试 | `production_task_id / attempt_id` | 每次试验留日志，失败可以没有可播放文件 |
| 媒体Take | `take_id` | 有有效媒体才必须绑定文件路径/哈希；失败尝试可无有效媒体但应有attempt_id |
| 生成指令 | `prompt_id@version` | 对应实际任务及上传绑定，不推断隐藏参数 |
| 后期母版候选 | `master_candidate_id@version` | 只由P9生成，不等于客户已批准 |
| 交付变体 | `delivery_variant_id@version` | 绑定具体市场/语言/画幅/时长及输出文件hash |
| 实际交付事务 | `delivery_id` | 与每次传输/签收对应，不与视频文件混同 |

- `source_mode`：`AI / LIVE / CG / HYBRID`；派生版本在实际内容、权利、字幕、语言或画幅变化时，应新建变体版本或`variant_segment_id`，不可自动复用原版G8通过结论。
- `shot_id`可被多个变体复用；同一镜头在9:16和16:9中可以采用不同入出点、重构图和take；用`variant_segment_id`区分实际使用，而不以强行重新编号为唯一方法。若导演设计实质成为新镜头，应另建`shot_id`。
- 不同视频片段、音频、静帧、字幕、动画图层均需可追踪源对象；`source_file_hash`用于文件完整性，不代表商业授权。

## R04｜统一状态机（按实体类型分离）

- `artifact_status`: `DRAFT → IN_REVIEW → APPROVED → LOCKED`，修订形成新版本，旧版标`SUPERSEDED`。
- `gate_decision`: `PASS/CONDITIONAL/REWORK/HOLD`，绝不写入`artifact_status`。
- `media_qa_status`: `UNREVIEWED/QA_PASS/QA_FAIL/EDITORIAL_ACCEPTED/RETIRED`；媒体可剪用性不代表G8商业批准。
- `delivery_status`: `NOT_RELEASED/APPROVED_FOR_DELIVERY/DELIVERED/RECEIPT_CONFIRMED/CLIENT_ACCEPTED`；所有状态有实际证据。
- `evidence_status`: `VERIFIED/CLIENT_SUPPLIED_UNVERIFIED/TO_VERIFY/REJECTED/EXPIRED/NOT_APPLICABLE`，并带证据有效期或审查日期。
- `rights_status`: `VERIFIED/RESTRICTED/PENDING/PROHIBITED/EXPIRED`；`VERIFIED`只在核对**具体作品、用途、渠道、地区、期限和修改范围**后成立。
- `data_status`: `MEASURED/PARTIAL/QUALITATIVE_ONLY/DATA_UNAVAILABLE`；P11未启动应另标，不冒称DATA_UNAVAILABLE已复盘。
- 旧文档中的`REVIEW`、`APPROVED_FOR_DIRECTION`、`G4_PASS`、`FINAL_CANDIDATE`等作为具体步骤的显示状态或子类型，不能替代以上根实体状态及其对应审查记录。

## R05｜分镜与预演、正式资产、正式媒体的可追溯界限

- P5决定视觉与摄影原则；P6可以使用`CONCEPT_REFERENCE`或`PROXY`进行Animatic；P7以G5批准镜头需求建立正式资产；P8生产真实take；P9编辑组合；P10完成逐变体批准。
- 在P6使用概念代理不等于拥有其商业发布权。若代理在后续实际成片、公开提案或商业发布中使用，必须分别取得对应授权。客户限制性素材从首次试用起遵守保密与上传约束。
- G5锁定的是镜头设计基线与必要传播任务；P7发现生产约束可以发起M02有范围的反馈，不可“反向修改分镜而不留版本”。
- G7a要求**可观察的动态验证证据或经批准的等效验证**。AI镜头默认草稿生成；实拍/CG可用测试镜头、技术预演、动作验证或其他充分证明替代，不要求虚构一个AI生成结果；成本高的例外需要风险批准及`exception_id`。
- G7b必须记录实际媒体及其商业可用性；P9允许提前做非锁定代理粗剪，但**不得以粗剪成功替代G7b或G8**。

## R06｜时间基准、跨版本与“内容”和“镜头”的对应关系

- P4的内容节拍时间（`beat_id`）是传播信息的规划轴；P6镜头时间轴是视频画面实际时间轴；P9时间线含声桥和重叠。三者不得作为同一个ID或把时长简单相加。
- 进入G5前，每个交付主版本需明确目标时基：`fps_num/fps_den`和非重叠画面成片区间`[in_frame,out_frame)`。叠化与声音重叠记录源时码和最终时间轴占用区间。
- 每个独立交付变体有独立`variant_timeline_id`、时长、字幕/产品/CTA安全区和权利范围。改变画幅、语言、时间长度应按内容影响重审，不能仅由P10-09导出技术文件便宣称通过。
- 影视短剧的单镜时长限制是该项目创作偏好而非商业广告行业统一硬标准。

## R07｜产品证据、含蓄宣称与品牌授权

- `claim_id`不仅覆盖广告文案，也覆盖通过产品动画、图表、动作演示、画面暗示表达的客观功效/功能；`non-factual_expression`可标记创意隐喻，但不能因此豁免可能导致误解的暗示审查。
- 一个宣称必须绑定指定产品SKU、市场、时间和适用限制；过期的价格、上市日期、测量数据和适用平台应复核，不得继承既往的`VERIFIED`状态。
- 项目中实际出现的Logo、包装、肖像、音乐、声音、字体和第三方素材必须保留使用范围许可；输入服务商、模型或平台的权利条款，不等于已获得所有第三方原始素材许可。
- 发现权利或事实BLOCKER时暂停受影响镜头/变体，执行最小范围回退和关联Gate复审。

## R08｜生产成本与重试归因

- 每笔原始费用以唯一`cost_entry_id`进入项目总账一次；分摊是分配视图，不重复新增原始成本。`rework_cost`是`actual_total_cost`的分析子集，禁止另加一遍。
- `ACTUAL`记录有支付、账单或有依据的实际用量计价信息；`ESTIMATE`、`COMMITTED`和预算保留单独类别；劳务成本按合同已发生费用与内部估算工时分开表达，不能假称全部已支付。
- 跨币种保存原币、汇率来源及折算日期。失败尝试通过`attempt_id`关联消耗，不要求失败产生视频文件。
- `G7a`必须查剩余可用预算与迭代上限，触发阈值后要求负责人审批，不虚构固定平台成本或通用失败阈值。

## R09｜P10成片候选与逐版验收

- P9生成`MASTER_CANDIDATE`并提交P10；P10-09可与内容审查交替进行，但**最终G8必须针对实际拟交付文件的hash**进行内容、技术、权利、地区和客户批准核验。只检查母版，不等于派生版本可放行。
- `G8 PASS`仅授权交付，不自动设置`DELIVERED`或`CLIENT_ACCEPTED`；合同约定的源工程可作为交付内容，但默认不包含所有编辑工程、模型或中间生成素材。
- 对作品集/模拟Brief，标`SIMULATED_APPROVAL`与`PORTFOLIO_CLOSE`，不得声称获得真实品牌批准、真实平台投放或客户验收。

## R10｜P11复盘与效果证据边界

- P11在合同/项目明确启用时执行；没有真实投放数据可完成制作成本和流程复盘，但不得评价真实转化效果。
- 各项KPI定义写明分子、分母、投放平台、样本范围、观察窗口和归因；`ROAS`不是`ROI`，广告支出和制作支出分开披露。
- 单次广告曝光/点击变化只支持描述，缺少可信对照时不得声称广告创意产生因果增量。复盘优化项须经责任人批准后才可改写正式SOP或Skill。

## R11｜跨阶段修订与审查失效

任何已冻结对象变更须记录：`change_request_id,source_artifact@version,change_reason,changed_fields,affected_ids,affected_variant_ids,proposed_cost_delta,decision_owner,approval_evidence,recheck_gates`。

失效判定以依赖影响为准：若只改动字幕排版，则重新检查P9包装/P10产品与变体/G8；若变动产品型号及证据，则重查P1/G1，可能进一步影响G2/G4/G5/G6/G7/G8。**不是所有返工都要从P0完整重跑**。

## R12｜真实执行前必须验证的剩余事项

S07审查的是文本标准与逻辑接口，**不是**实际商业项目投放或全面合规认证。第三阶段仍需建立操作说明、可填写模板、自动化接口校验、抽样试跑及项目级配置。新型号/模型/投放渠道/所在法域的条款须在具体任务时重新核验。
