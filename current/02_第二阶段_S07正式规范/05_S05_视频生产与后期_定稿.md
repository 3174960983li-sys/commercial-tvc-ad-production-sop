## 0｜适用条件、责任边界与工作顺序

### 0.1 阶段职责

| 层级 | 唯一主要任务 | 准入及交付 | 不得擅自替代 |
|---|---|---|---|
| P6（上游） | 锁定`shot_id`、镜头任务、动作、机位、相邻接缝、Animatic | G5分镜、`shotlist_version` | P8/P9不能暗改镜头叙事与切点 |
| P7（上游） | 提供资产母版、变体、真实参考、使用权与生产模式 | G6资产包、Shot–Asset映射、`production_plan` | P8不能改变产品型号、Logo、人物身份、场景结构 |
| **P8** | 按已批准条件试产、验证、生产、筛选合格镜头 | 草稿Gate G7a、正式镜头Gate G7b、`take_id`及生成/成本日志 | 不决定品牌新宣称；不以改提示词之名修改分镜 |
| **P9** | 以批准素材剪辑成广告并进行合成、调色、声音与品牌包装 | 可复现剪辑工程、母版候选及P10审查包 | 不越权更改脚本核心信息、品牌资产或客户批准的内容 |
| P10（下游） | 完整成片商业、技术、合规审核及客户交付 | G8最终批准及各投放版本交付 | P9内部签核不构成客户最终验收 |

### 0.2 强制前置条件

- **P8启动：** `G6=PASS`；镜头表、Animatic、导演规则、正式资产及生产技术方案的有效版本一致；镜头级预算、技术指标、权利和风险有责任人。若缺失阻断性资料，则`HOLD`受影响的镜头，不影响其他已满足条件的镜头。
- **G7a之前：** 草稿已经证实该镜头的关键动作、构图、主体、产品信息、运动与剪辑接缝可实现。未经草稿验证或没有获准例外，不能启动高成本高清生产。
- **G7b之前：** 正式镜头文件已经过人工或经验证的检测流程审查，且交给P9的媒体规格与元数据完整；存在阻断性错误的`take_id`不得标记`EDITORIAL_ACCEPTED`。
- **P9正式锁定：** G7b通过。为加快制作，可在G7b前使用临时素材制作`OFFLINE_PREVIEW`，但不能把临时版作为正式画面批准依据，所有正式替换均须可追溯。
- **P9准出：** 形成供P10审核的母版候选、项目工程、素材与权利清单、技术预检和开放问题清单。**P9输出不等于G8通过。**

### 0.3 责任划分：个人与小团队

| 决策职责 | 个人模式 | 小团队模式 | 强制批准约束 |
|---|---|---|---|
| 镜头可行性/草稿 | AI导演兼生成操作者 | 导演＋AI视频负责人 | 需有G7a审核记录；产品事实经授权方核对 |
| 正式镜头与来源记录 | 一人制作并独立记录 | AI制作、制片、素材管理员 | G7b必须能追溯镜头和权利 |
| 剪辑与声音 | 兼任剪辑/音频，按清单自审 | 剪辑、合成、调色、混音分工 | 不能伪造客户批准或法务授权 |
| 预算/变更 | 独立登记成本与变更 | 制片/项目经理管理 | 超出审批预算时需重新取得授权 |
| 最终商用签收 | 作品集注明模拟 | 客户授权代表 | 真正的G8/交付验收由P10管理 |

### 0.4 不可变约束

1. 商业不可变项：品牌、产品型号/包装、批准`claim_id`、`copy_id`、CTA、禁用词与地区渠道限制。
2. 视觉不可变项：已批准`shot_id`的传播任务、机位与动作意图、人物和产品身份、场景锚点、关键初末态。
3. 素材不可变项：引用的资产和版本必须真实存在且具有合规使用权；临时代理不是正式商用素材。
4. 声音不可变项：批准的旁白原文、说话人身份与明确规定的声画关系，不能为模型便利删改。
5. 版本不可变项：任何已锁定文件只可被新版本取代，不得原地覆盖；修改和跨阶段回退由M02/M09管理。

### 0.5 制作路线的一致性

`source_mode = AI | LIVE | CG | HYBRID`。这里的`HYBRID`表示一个镜头同时采用两种或以上生产来源，不代表AI对实拍素材具有额外的默认使用权限。P8对实拍/CG镜头同样维护`take_id`、素材来源、权利、镜头状态和质检；AI专有的提示词与模型日志在非AI镜头标`N/A`并写明原因。`P8-02`针对**镜头级中间帧和补充素材**，不能用来无批准重建P7产品资产母版。

  ├─ G4: script_id / beat_id / director_rule_id
  ├─ G5: shot_id + shotlist_version + animatic_version
  ├─ G6: asset_id@version + production_plan_id
  ├─ P8: production_task_id
  │   ├─ prompt_id@version       [AI时]
  │   ├─ image_id@version        [关键帧时]
  │   ├─ take_id@version         [每次生成/拍摄/渲染]

说明：`shot_id`表示导演镜头任务，不是一段视频文件；`take_id`表示一次真实生成、拍摄或渲染素材；`production_task_id`表示实际制作工作项。同一镜头可存在多个take；同一生产任务可为多个镜头服务，但必须有明确剪辑及追溯关系。`selected_take_id`必须是已存在且有效的take；切勿用`shot_id`伪装成媒体文件名。

| 生产任务 | `PLANNED` / `READY` / `RUNNING` / `PAUSED` / `COMPLETED` / `CANCELLED` |

| 成片候选 | `OFFLINE_PREVIEW` / `ROUGH_CUT` / `FINE_CUT` / `MASTER_CANDIDATE` / `REJECTED`；`APPROVED_MASTER`只在G8后 |

### 3.4 成本核算原则与公式

**基础核算单位**：同时支持镜头（`shot_id`）、生成任务（`production_task_id`）、批次（`batch_id`）和广告项目（`project_id`）。每一笔花费只能进入总账**一次**；不同维度是分摊视图，不是重复相加。

| 项目 | 定义及核算规则 |
|---|---|
| `direct_generation_cost` | 本镜头所有实际生成、渲染或采集的直接消耗（含失败和已废弃尝试） |
| `asset_preparation_cost` | 镜头专属资产成本；共用资产按事先确定的分摊方法处理，不得多次全额计入 |
| `post_repair_cost` | 由该镜头引起的后期修复及重合成追加成本；区分常规后期预算 |
| `rework_cost` | 相对于首次获批方案，多出且可归因于返工的追加成本，标记为跨费用项**分析维度**，不与总账另加一次 |
| `approved_budget` | P7-08及项目批准上限，预算变更须留版本 |
| `committed_cost` | 已预留/承诺但未实际发生的金额，**不得写作实际消耗** |
| `actual_cost` | 已实际计费/支付/可核验的资源消耗，按币种和原始计费凭证记录 |
| `estimated_cost` | 无法取得即时消费记录的估算，必须与真实成本分开 |

**非重复计费公式：**

- `项目实际总成本 = Σ unique(cost_entry_id 的 ACTUAL 金额)`（按统一计价币种；原币金额和汇率来源保留）。
- `镜头可归属成本 = Σ 该镜头独占成本 + Σ 已审批共用成本分摊`（每笔共用成本跨镜头分摊之和不超过原始金额）。
- `项目返工成本 = Σ 被标记为REWORK且实际发生的cost_entry_id金额`；它**包含于**项目实际总成本，不得再加一次。
- `剩余预算 = 当前已批准预算 - 实际成本 - 尚未发生但已承诺支出`；估算和未开票情况应分别说明。
- 可选：`成本节省率 = (同规格可比基线成本 - 本次实际成本) / 同规格可比基线成本`，若没有等价基线不得声称节省百分比。

项目设置`warning_budget_threshold`和`retry_cap_per_shot`作为可配置的审批条件，**不强加“失败3次必须换模型”等伪行业硬标准**。达到阈值即触发负责人审查：继续重试、拆镜、局部修复、换路线或回退P6/P7。

### 3.5 缺陷诊断与返工权限

| 缺陷根因 | 指向步骤 | 放行条件 |
|---|---|---|
| 文字/提示词表达歧义 | P8-03 | 新prompt经对照验证，生成新的take与QA记录 |
| 模型运动/动作能力不足 | P8-03/04/06或改生产路线P7-08 | 替代技术通过草稿；改变分镜须重审G5，改生产计划须按G6权限确认 |
| 产品、人物、场景母版错误 | P7-01～06 | 正确资产版本批准，受影响镜头重新测试与审核 |
| 起落幅/轴线/镜头时长设计错误 | P6-03～10 | 分镜通过修订及必要G5重审，相关任务/素材重新映射 |
| 商业卖点、广告宣称错误 | P1/P2/P4 | 有权批准人纠正，相关G1/G2/G4复核后才能制作/交付 |
| 单纯编辑/混音/包装错误 | P9相应步骤 | 后期修订并重新内部审片，涉及关键商业项需P10复核 |
| 合规授权缺失 | P7/M08与P10相关责任 | 获取真实许可或更换素材；不能以技术修复掩盖 |

## 4｜G7a / G7b 两层生产审核

### 4.1 Gate对照

| 要素 | G7a：草稿可行性放行 | G7b：正式镜头可用性放行 |
|---|---|---|
| 主要对象 | `DRAFT` take、关键动作/机位/镜头初末态 | `FINAL_CANDIDATE` take、QA与媒体/权利信息 |
| 核心问题 | 是否有证据证明镜头值得进入正式生产？ | 素材是否可供P9正式编辑、合成和商用审片？ |
| 商业检查 | 产品/品牌正确、关键展示可辨、画面不传达虚假功能 | 逐帧产品/Logo/卖点准确，正式画面无相关失真 |
| 技术检查 | 动作、相机路径、物理、接缝、风险和成本可行 | 真实媒体规格、素材完整性、入出点、色彩/音频可交接 |
| 成本检查 | 已发生草稿成本、后续预算、受控重试或替代方案 | 高清实际消费、失败成本、额外修复预算、素材入选依据 |
| 决策结果 | PASS / CONDITIONAL / REWORK / HOLD | PASS / CONDITIONAL / REWORK / HOLD |
| 放行结果 | 授权对应镜头进入正式高清制作 | 授权对应take进入P9正式后期 |

**G7a的`CONDITIONAL`**仅允许尚未完成、但不影响镜头技术和商业真实性判断的文书性条件；产品事实、关键动作、主要构图、必需授权或镜头衔接未证实时不能放行。若为紧急例外跳过草稿，必须有经批准的明确成本风险、替代验证证据和`EXCEPTION_ID`，不得默认等同G7a通过。

**G7b的`CONDITIONAL`**仅允许已具备可编辑主素材、且剩余问题有已批准的P9修复路径的非关键项；任何品牌/产品事实、权利、不可剪接或阻断性技术缺陷必须`REWORK/HOLD`。`APPROVED_ASSET`不等于`EDITORIAL_ACCEPTED`，正式镜头必须通过独立QA。

### 4.2 每镜头必须附带的Gate记录

`gate_id | project_id | shot_id | reviewed_take_ids | shotlist_version | asset_versions | preview_or_final_hash | qa_ids | critical_findings | rights_status | actual_cost_to_date | remaining_budget | decision | reviewer | date | approval_evidence | exceptions | recheck_required`

### 4.3 重审触发

- G7a通过后，换模型/生成模式/关键输入素材/运动实现路径，若影响已验证条件，重新G7a或等效批准；仅文件名变化不需无意义重审。
- G7b通过后替换入选take，至少重新做素材QA及G7b入选变更确认；涉及视频内容、时长或动作改变时需重查相邻切点与P9时间线。
- 修改锁定分镜/脚本/资产的上游变更，回到对应Gate；G7a与G7b的原审查不自动沿用于新版。
- P9后期生成的新合成视频可由P9审查；如果改变take所承载的关键动作/产品内容或需替换镜头来源，重新考虑G7b和上游审批。

## 5｜P9统一后期工程、媒体与版本交付结构

### 5.1 工程结构与追踪要求

| 产物 | 必填关联与最小属性 |
|---|---|
| `edit_project` | `edit_project_id/version`、所属母版、剪辑软件/版本、素材映射、工作时基、备份、负责人 |
| `timeline` | `timeline_id/version`、`sequence_order`、片段入出点、`shot_id/take_id`、图形和声轨Cue、输出版本 |
| `comp_pass` | `comp_id`、对应镜号/片段、修复目的、图层/镜头来源、前后比对、权利与审查状态 |
| `grade_pass` | `grade_id`、色彩输入/工作/输出、品牌色保护、监看条件、审查状态 |
| `audio_package` | `mix_id`、music/voice/sfx来源与使用权、声轨位置、目标响度/峰值规范和实测值 |
| `graphics_package` | `graphic_id`、官方Logo/字体、`copy_id/claim_id`、语言版、安全区、可读时长及审批记录 |
| `master_candidate` | `master_candidate_id/version`、文件hash、实际编码/时长/色彩/音轨、所依赖工程、开放问题 |

### 5.2 媒体接口标准

- 不强制所有项目输出特定FPS、码率、分辨率、采样率或LUFS；以`P0交付矩阵 + 实际平台/广告主技术说明 + 项目后期工作规范`共同确定，并记录其来源及核对日期。
- 保留`source_media`原件；代理文件必须记录`proxy_of`与源文件hash；视频转码不默认可修复帧率不匹配、运动模糊或色彩转换错误。
- 对混合素材必须显式标记AI/实拍/CG来源、时基、色彩空间、镜头方向、声音同步状态；禁止仅用同一文件扩展名认定完全兼容。
- 发现需要在后期补足的图层，应清晰标记 `TO_COMPOSITE / TO_REPLACE_GRAPHIC / APPROVED_EFFECT`，不能依赖生成时模糊的Logo文字直接通过。
- 语音、音乐、字幕、多语言版本、静音播放版本可作为条件要求；平台或客户未要求时标记`N/A`，不能凭空增加收费或交付范围。

### 5.3 包装文字与产品事实审查顺序

`P4批准文案 / P1证据 → P7官方商标和产品素材 → P9合成、字幕、片尾或角标 → P10商业与合规复核`。

同一品牌文案可能同时出现在画面内产品包装、独立字幕与片尾包装，三处需分别检查；即使内容相同，也不能假定生成图像内的文字是准确的。

### 5.4 母版与派生版本管理

- `master_family_id`指定同一广告概念下母版及衍生交付；`parent_master_version`记录每个改编版本的基线。
- 画幅适配、15秒/30秒版本、多语言版和静音版应维护独立`delivery_variant_id`，不得直接裁切后不检查产品和文案可读性。
- 交给P10的是`MASTER_CANDIDATE`及对应工程/证据；G8 PASS之后才能被标为`APPROVED_MASTER`或“客户已批准”。
- 同一广告存在多个品牌/地域主体时，产品信息、宣称证据与使用权可不同，须逐版本确认而非自动继承。

## 6｜按广告类型和生产方式的差异化检查

| 广告路线 | P8重点风险 | P9重点验收 |
|---|---|---|
| 高端品牌TVC/形象广告 | 视觉调性漂移、人物/场景一致性、象征性特效失控 | 电影感与品牌识别平衡、音乐授权、视觉/声音完整度 |
| 产品展示广告 | 外形/结构/文字变化、透明/反射材质、功能演示真实性 | 精准产品特写、包装逐字核对、材质与产品色彩一致 |
| 科技产品广告 | 接口/按钮/屏幕UI虚构、功能演示与型号不符 | 合规功能可视化、CG/实拍合成、UI文字校验 |
| 创意概念广告 | 超现实物理变化影响观众理解、隐喻脱离品牌 | 情绪推进、品牌出现的时机和可辨度 |
| 电商信息流/效果广告 | 主卖点缺失、素材跑偏、CTA缺乏视觉承载 | 前段信息到达、无声理解、CTA与落地页信息一致 |
| 社交媒体/多画幅广告 | 竖屏裁切破坏产品构图、人物手势与字幕冲突 | 平台安全区、字幕与品牌露出、多比例逐版审片 |
| 活动/新品发布广告 | 发布日、促销/价格、限定信息等时效性内容生成错误 | 时间和价格版本、地域差异、临期更新可替换 |
| AI+实拍/CG混合 | 不同来源运动轨迹/空间/光影和视角难匹配 | 跟踪、抠像、阴影、质感、色彩/音频接口与权利 |

**项目不采用同一种广告模板强制覆盖全部路线。** 例如部分品牌形象片没有直接购买CTA，但仍要明确最终想形成的品牌认知；部分效果广告需要更密集的信息结构，但仍须保护产品真实性和合法宣称。

提示词书写注意事项（标准层要求，具体操作在第三阶段）：主体名称与动作归属明确；跨镜相邻视频的机位变化及状态承接明确；镜头起幅/运动/落幅/声音保留；只有在真实平台支持时才使用其专有格式或媒体槽位。不得以“模型做不到”为由在提示词内静默改变导演设计。

### 8.3 综合错误回退矩阵

|---|---|---|---|
